## 5. 具体修改建议

### 5.1 先防止合并、误删和无必要的主体扩写

当前prompt已有保留独立结构要求，建议改成操作前执行的判定，而不是继续重复禁止语句。可采用以下表述：

```text
对每条准备修改的三元组，先指出主体、关系、客体或必要限定中具体错误的部分。
如果相关关系已由其他三元组表达，先核对现有结构是否已经表达完整，再决定是否补入限定。
确实存在错误时，优先修改错误字段，保留其他正确内容。
独立关系表达不准确时，修正这项关系，不因其文字可以放进另一条长三元组就直接删除。
缺少条件会改变关系是否成立时，保留必要条件，并检查其他仍需独立表达的关系是否保留。
```

依据4.1—4.4。原is in类别条目未完全对齐Gold，保护它不等于宣称它已经正确。应修正表达，避免一删了之。短阈值与独立类别的组合是本套Gold中的具体方式，需用开发示例说明；不能把所有必要条件都从关系中拿掉。

### 5.2 区分并列、选择和真正重复

```text
多个对象分别参与同一关系且符合标注规则时，分别保留；and本身不是合并依据。
对one of、at least one of等选择表达，保留完整选择范围，不断言每个选项都必然成立。
重复判断比较主体、关系、客体和必要限定是否表达同一项关系。
长字段中出现另一条关系的文字，不足以证明另一条独立关系重复。
删除重复项前，指出最终保留的对应独立条目和index。
```

依据4.3。程序层面可先做保守对照：重复删除只自动接受字段规范化后完全相同、且属于同一句实例的条目，其他删除记录供核查。这会限制同义去重，且无法单独防止replace改坏内容，不是永久取消全部remove。无依据且不可修复的内容仍需单独处理。

### 5.3 改善语义比较：让差异说明具体变化

当前比较prompt已列出情态、条件、目的等检查项，重点是补短例和输出判据，不必首先改成每句独立调用。建议：

```text
分别核对主体、动作或状态、对象，以及否定、可能性、能力、条件、目的和因果。
两侧出现相同词语，不代表这些词语之间的关系相同。
遇到“能够做→实际做”“为了做→并列动作”“有条件→无条件”等变化，
指出源表达、重建表达及具体改变的含义；不改变含义的改写不报告为错误。
```

依据4.5/4.6，可用capable of storing与stores、query to identify与query and identify作开发例子。文本比较仍负责语义差异，SPO结构由反馈直接检查，不能要求自然语言重建可靠保存所有字段边界。

### 5.4 防止有效提示未落实：保存可核对的处理记录

每条非空差异记录一个简短决定：修改、已有条目表达、重建错误、差异误报或暂无法确认。包含sentence_id、差异编号、相关index和对应操作；不要求长篇内部推理。以下只是建议结构，不是本轮实际输出：

```json
{
  "sentence_id": "S2",
  "difference_id": "A0",
  "decision": "modify",
  "triple_indices": [
    19,
    20
  ],
  "operation_refs": [
    "replace:19",
    "replace:20"
  ],
  "summary": "修复查询与识别、确定之间的目的关系"
}
```

依据4.5。最终核对标为修改的事项是否确有对应操作。填写记录不保证判断正确，还需Gold检查。现有解析/执行接口要求add/remove/replace结构，不能直接添加字段后假定兼容；可单独保存审校记录，或配套调整解析并保持操作接口兼容。

### 5.5 修改“长字段已有就跳过”的覆盖判据

当前规则：

```text
内容已在长字段中，仅缺少独立表达：属于拆分问题，按已有内容处理。
```

建议替换为：

```text
内容已经出现在某条三元组的长字段中时，继续判断它是否表达另一项独立关系。
该关系符合抽取规则且当前集合没有对应独立三元组时，补充。
只是已有关系的修饰，或已有独立三元组已经表达时，保留现有结果。
判断覆盖时核对主体、关系、客体与必要限定，不只检查相关词语是否出现。
```

依据4.7—4.9、4.15。这意味着反馈明确承担拆分遗漏的补查，与拆分agent部分重合是有意的职责选择。不能由此机械拆开所有长短语，也不应重复添加已有关系。

当前prompt已有源句优先步骤。关键变化是：源句关系候选→实际SPO对应→判断正确/需修正/缺独立表达→操作→核查保留结果；重点在覆盖判据，不是只把标题改成执行步骤。

### 5.6 统一标注方式，同时检查程序去重

从开发集Gold归纳简短约定供抽取、拆分、反馈共享，不需要将测试Gold作为运行输入。本轮案例用于开发回归，再用独立文档验证，避免只适配这五篇。

| 约定 | 需明确的内容 | 案例 |
| --- | --- | --- |
| 独立关系 | 定义、归属、目的、条件中的关系何时单列 | 4.7—4.9 |
| 并列与组合 | 分别成立、选择范围、保留整体的区别 | 4.3、4.11 |
| 字段边界 | 完整谓词、目的词及介词如何分配 | 4.5、4.10 |
| 主体与方向 | 谁参与哪项关系，指代及主动被动约定 | 4.8、4.13 |
| 实例与去重 | 同句重复和不同句分别出现如何处理 | 4.12 |

尤其需要核查整篇去重：若Gold按句保存相同关系的两个实例，模型补出后又按SPO合并，光改反馈prompt无效。这不要求跨句抽事实，而是保留每条事实自己的源句实例。改变去重也可能增加重复，必须与固定Gold评分共同验证。

Gold中的拼写、近重复字段划分、选择性省略与语义漏抽分开记录。评价仍只用Gold，但不能承诺一条通用规则就能复现所有不一致的标注取舍。

### 5.7 来源恢复应在重建前检查

在分组前恢复可确定的来源，检查每句条目与UNASSIGNED；不能为了让空组非空而猜来源或添加重复三元组。对仍未定位内容保留状态，结合全文核实，不把未定位直接判成源文不支持。

依据4.2、4.4、4.13、4.14。来源修复本身不改变SPO评分，不保证阻止合并和误删；修好定位后仍要核查三元组内容。

## 6. 固定输入的验证顺序

固定143条拆分结果、源文和146条Gold。反馈改动先保持重建/差异输入不变；重建、比较改动单独测试，避免混入上游变化。保存实际prompt、模型设置、响应、接受/拒绝操作、审校记录和最终SPO。考虑输出波动，关键结论应重复运行并在独立文档验证。

| 实验 | 改动范围 | 重点观察 |
| --- | --- | --- |
| A 防退化 | 操作判据与删除保护 | S8/S10阈值保住；类别/equivalents保留或修正；S7不盲目扩写 |
| B 补结构 | 在A基础上改长字段覆盖规则 | exceeds、systems include、free of等独立关系是否补出 |
| C 落实提示 | 保存并校验差异处理记录 | doc0/S2有对应修复；误报引用已有条目而不重复新增 |
| D 改对比 | 固定三元组与重建，调整比较示例和判据 | capable/stores等是否报出，有无新增误报及下游收益 |
| E 来源与去重 | 分别测试前移来源恢复、按句实例去重 | 错位减少；相同事实的不同源句实例是否保留 |

这是用于定位效果来源的顺序，不是要求一次全部改动。每步同时比较严格/宽松P、R、F1，核对新增正确关系、已有关系损失、额外预测和无关弱配对；来源变化单独统计。

正向对照必须保留：doc1/S1的严重程度新增应仍成功。不能只因删除少了、条目多了、每条提示都有状态，就认定方案有效。

## 7. 不能越过的归因边界

1. doc4合并、删除、长主体回填有直接证据，且比较并未明确要求这些操作；主要退化指向反馈判断，不等于证明所有内部原因。
2. 来源错位和比较漏检已确认，但它们是否诱发具体误删，需要固定其他条件的对照。
3. 局部目标Gold更接近不保证全文评分提高；S7涉及配对竞争，不能相加配对F1当作总体贡献。
4. 未配对不全是新事实缺失；已配对不保证语义正确，详见第二阶段的跨源句无关弱配对。
5. 当前代码规则与本轮实际完整prompt须区分；本文只提出建议，未修改程序，也未声称验证有效。
