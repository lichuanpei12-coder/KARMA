# 按源句分组的反馈

默认流水线使用 `source_sentence_groups_v1`，不需要额外开关。

## 编号与来源

- 源句：本次抽取文本中带 `sentence_id` 的原文句子，编号为 S1、S2……，每篇重新编号。
- JSON 数据集已有句子数组时优先保留其边界。普通文本用本地规则断句；若启用摘要并改变了文本，则对实际抽取文本断句。
- 三元组保存 `source_sentence_ids`，可关联多个源句；`evidence` 保存抽取 context 或修订 evidence。
- 三元组 `index` 仍然是当前阶段的全局列表编号，分组不会重新编号。拆分后继承来源，去重时合并来源编号。
- 旧基线没有来源字段时尝试依据原文精确匹配恢复；无法恢复的条目保留在 `UNASSIGNED` 组。该组表示未定位，不代表无效或应删除。
- 空源句组保留。分组表示来源关系，不保证该句所有事实已被抽取，也不强制补造一条关系。

## 调用流程

1. 第一轮抽取接收带编号的源句，返回三元组及来源编号。
2. 拆分继承父三元组来源信息。
3. 重建每篇一次调用，分别输出各组文本。只输入编号和三元组，不输入源句正文及证据，避免从原文补回漏抽信息。
4. 对比每篇一次调用，输入全文和各组源句、重建文本，按编号输出差异，空组也参与。
5. 实体修订和关系修订保留分组差异。关系修订使用源句分组及全局 index 定位 add/remove/replace。

模型输出漏掉编号、重复编号或返回无效编号时：重建回退为各组原三元组的字面表达并标记 `literal_fallback`；对比标记 `failed`，不声称无差异。完整反馈仍交给修订环节核对源文。

## 查看结果

- `baseline.json`：保存每篇 `source_sentences` 和三元组来源，可直接回放。
- `_dump_docN_feedback.json`：新增 `source_sentences`、`sentence_groups`、`reconstructions`；`diff.sentence_differences` 保存每句差异及处理状态。
- `_dump_docN_revision_result.json`：新增拆分后、反馈后、最终的句子分组。各组 index 对应该阶段的三元组列表。
- `_run_manifest.json`：记录分组版本、源句及代码摘要。

原有 text_a、text_b 和顶层两组差异仍保留。顶层差异加 `[S1]` 等前缀便于定位；分析时优先读取结构化的 `sentence_differences`。

验证使用离线模型替身，覆盖编号传递、空组、跨句关联、拆分继承、去重、旧格式恢复、异常输出和基线回放。未据此认定真实模型的 P、R、F1 已提升，需在固定输入和 Gold 的实验中验证。
