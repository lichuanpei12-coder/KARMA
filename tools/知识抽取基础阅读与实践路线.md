# 知识抽取基础阅读与实践路线

## 1. 文档目的

本目录用于补充“工业多源异构数据知识抽取”研究所需的基础知识。推荐内容聚焦知识抽取本身，不展开数据挖掘、RAG、GraphRAG、知识图谱问答或复杂 Agent 应用。

当前学习目标不是立即设计一个庞大的多智能体系统，而是逐步回答以下问题：

1. 知识抽取的输入和输出分别是什么？
2. 实体、属性、关系和事件有什么区别？
3. Schema 如何定义抽取目标并约束输出？
4. 规则、监督模型、生成模型和 LLM 分别如何完成抽取？
5. OpenIE、Closed IE、Universal IE 和 Schema-guided IE 有什么区别？
6. 如何评价抽取结果，发现并修正错误？
7. 如何把抽取结果转化为可进入知识库的规范化知识？

## 2. 首先建立的概念体系

### 2.1 信息抽取与知识抽取

信息抽取（Information Extraction，IE）是从自然语言或文档中识别结构化信息的过程，主要任务包括：

- 命名实体识别（NER）：识别设备、部件、材料、故障等实体；
- 属性抽取：抽取型号、数值、单位、状态等属性；
- 关系抽取（RE）：识别实体之间的语义关系；
- 事件抽取（EE）：识别事件类型、触发词及参与者；
- 文档级信息抽取：利用跨句上下文、指代和篇章信息完成抽取。

知识抽取通常强调：抽取结果应具有明确语义，并能够映射到知识库、知识图谱或其他结构化知识表示中。因此，知识抽取往往还涉及 Schema 映射、规范化、去重、验证和来源记录。

### 2.2 四类常见抽取范式

#### Closed IE

预先规定实体类型和关系类型，例如：

```text
实体类型：Equipment、Component、Fault
关系类型：has_component、has_fault、located_at
```

优点是输出容易控制和评价，适合目标明确的工业场景；缺点是难以发现 Schema 外的新知识。

#### OpenIE

不预先限定关系类型，直接从文本中抽取开放三元组：

```text
(泵P-101, 安装在, 反应装置A区)
```

优点是覆盖广；缺点是关系表达容易碎片化、同义化，难以直接进入统一知识库。

#### Universal IE

用统一模型和统一输出形式处理实体、关系、事件等多类任务，通常通过 Schema Prompt、结构化语言或代码表示任务。

#### Schema-guided IE

由 Schema 明确规定需要抽取的实体、属性和关系。它最贴近当前工业知识抽取方向。Schema 不应只有标签名称，还应包含：

- 类型定义；
- 正例与反例；
- 实体边界规则；
- 允许的关系主体和客体类型；
- 属性类型、单位和基数；
- 必填约束与互斥约束。

## 3. 必读的基础论文

这些论文不全是最近两年发表，但构成理解现代知识抽取方法的基础。

### 3.1 Open Information Extraction from the Web

- 会议：IJCAI 2007
- 作用：OpenIE 奠基工作，解释为什么要在没有预定义关系的情况下从大规模文本发现关系。
- 阅读重点：OpenIE 的任务定义、输入输出、自动生成训练数据的思想。
- 不必深挖：早期分类器的全部实现细节。

### 3.2 Open Information Extraction: The Second Generation

- 会议：IJCAI 2011
- 系统：ReVerb
- 作用：通过句法和词汇约束减少无意义、非完整关系。
- 阅读重点：规则和约束如何影响 Precision 与 Recall。

### 3.3 ClausIE: Clause-Based Open Information Extraction

- 会议：WWW 2013
- 作用：根据从句结构和依存句法抽取命题。
- 阅读重点：传统句法方法如何从句子结构得到关系及参数。

### 3.4 REBEL: Relation Extraction By End-to-End Language Generation

- 会议：Findings of EMNLP 2021
- 论文：https://aclanthology.org/2021.findings-emnlp.204/
- 代码：https://github.com/Babelscape/rebel
- 作用：把关系抽取转化为序列到序列生成任务。
- 阅读重点：三元组如何线性化；生成式关系抽取与分类式关系抽取的区别。

### 3.5 Unified Structure Generation for Universal Information Extraction（UIE）

- 会议：ACL 2022 Long Paper
- 论文：https://aclanthology.org/2022.acl-long.395/
- 代码：https://github.com/universal-ie/UIE
- PaddleNLP 实现：https://github.com/PaddlePaddle/PaddleNLP/tree/develop/slm/model_zoo/uie
- 作用：将实体、关系、事件和情感抽取统一成文本到结构生成任务。
- 阅读重点：统一结构表示、Schema Prompt、不同抽取任务如何统一。

### 3.6 DeepKE

- 会议：EMNLP 2022 System Demonstration
- 论文：https://aclanthology.org/2022.emnlp-demos.10/
- 代码：https://github.com/zjunlp/DeepKE
- 作用：提供实体、属性、关系、文档级、低资源和多模态知识抽取工具。
- 阅读重点：不同任务的数据格式、训练流程和评价流程。
- 实践价值：适合用来理解传统监督模型到 LLM 抽取之间的差异。

## 4. 2024—2026 年优先阅读的顶会论文

### 4.1 GLiNER

- 论文：GLiNER: Generalist Model for Named Entity Recognition using Bidirectional Transformer
- 会议：NAACL 2024 Long Paper
- 论文：https://aclanthology.org/2024.naacl-long.300/
- 代码：https://github.com/urchade/GLiNER
- 难度：低，适合第一个运行。
- 核心问题：如何根据用户给出的任意实体类型进行开放类型 NER。
- 学习价值：理解实体类型、实体边界、零样本抽取以及轻量模型与 LLM 的区别。

### 4.2 UniversalNER

- 会议：ICLR 2024
- 论文：https://proceedings.iclr.cc/paper_files/paper/2024/hash/34678d08b36076de986df95c5bbba92f-Abstract-Conference.html
- 代码：https://github.com/universal-ner/universal-ner
- 核心问题：如何把大模型的开放实体识别能力蒸馏到较小的专用模型中。
- 学习价值：理解开放类型 NER、知识蒸馏、跨领域泛化和大规模 NER 评测。

### 4.3 GoLLIE

- 论文：GoLLIE: Annotation Guidelines Improve Zero-Shot Information-Extraction
- 会议：ICLR 2024
- 论文：https://openreview.net/forum?id=Y3wpuxd7u9
- 代码：https://github.com/hitz-zentroa/GoLLIE
- 项目主页：https://hitz-zentroa.github.io/GoLLIE/
- 核心问题：模型如何遵循详细标注指南，在未见过的 Schema 上抽取实体、关系和事件。
- 学习价值：理解“Schema 不等于标签名称”，以及定义、规则、示例和反例如何控制抽取。
- 难度：中高；模型至少为 7B，可先阅读 Notebook 和任务定义。

### 4.4 KnowCoder

- 论文：KnowCoder: Coding Structured Knowledge into LLMs for Universal Information Extraction
- 会议：ACL 2024 Long Paper
- 论文：https://aclanthology.org/2024.acl-long.475/
- 代码：https://github.com/ICT-GoKnow/KnowCoder
- 核心问题：如何用代码表示 Schema，并让 LLM 通过代码生成完成通用知识抽取。
- 学习价值：理解类型系统、代码表示、复杂结构输出和 Universal IE。
- 难度：高；现阶段以读懂 Schema 表示和推理示例为主。

### 4.5 Learning to Extract Structured Entities Using Language Models

- 会议：EMNLP 2024 Main Conference
- 论文：https://aclanthology.org/2024.emnlp-main.388/
- 代码：https://github.com/microsoft/Structured-Entity-Extraction
- 核心问题：如何抽取带有内部属性结构的复杂实体，而不只抽取一个实体名称。
- 学习价值：理解多阶段结构化实体抽取，以及 AESOP 等非严格匹配评价方法。

### 4.6 Extract, Define, Canonicalize（EDC）

- 论文：Extract, Define, Canonicalize: An LLM-based Framework for Knowledge Graph Construction
- 会议：EMNLP 2024 Main Conference
- 论文：https://aclanthology.org/2024.emnlp-main.548/
- 代码：https://github.com/clear-nus/edc
- 核心流程：开放抽取 → 关系定义 → Schema 规范化。
- 学习价值：理解开放关系如何转化为可进入知识图谱的规范关系，以及如何在没有 Schema 时诱导 Schema。
- 与当前研究的关系：非常直接，是最值得实际运行的项目之一。

### 4.7 OneKE

- 论文：OneKE: A Dockerized Schema-Guided LLM Agent-based Knowledge Extraction System
- 会议：WWW 2025 Companion/Demo
- 论文：https://arxiv.org/abs/2412.20005
- 代码：https://github.com/zjunlp/OneKE
- 核心问题：如何以 Schema 为指导，从网页、文本和 PDF 中完成多任务知识抽取。
- 学习价值：观察 Schema Agent、抽取 Agent、错误案例库和完整系统的组织方式。
- 注意：先研究一条最简单的文本抽取路径，不要一开始分析全部 Agent。

### 4.8 GLiNER2

- 论文：GLiNER2: Schema-Driven Multi-Task Learning for Structured Information Extraction
- 会议：EMNLP 2025 System Demonstration
- 论文：https://aclanthology.org/2025.emnlp-demos.10/
- 代码：https://github.com/fastino-ai/GLiNER2
- 核心问题：把开放实体识别扩展到 Schema-driven 多任务结构化抽取。
- 学习价值：工程上容易使用，适合快速构建基线。
- 注意：这是 Demo Track，学术权重不能简单等同于 EMNLP 主会长文。

### 4.9 AutoSchemaKG

- 论文：AutoSchemaKG: Autonomous Knowledge Graph Construction through Dynamic Schema Induction from Web-Scale Corpora
- 会议：ACL 2026
- 论文：https://arxiv.org/abs/2505.23628
- 代码：https://github.com/HKUST-KnowComp/AutoSchemaKG
- 核心问题：从大规模文本中动态诱导 Schema，并自动构建知识图谱。
- 学习价值：理解自底向上的概念化、Schema induction 和动态 Schema。
- 难度：高；现阶段只做小规模 Schema induction 实验，不复现全量系统。

## 5. 推荐阅读顺序

### 第一阶段：理解任务

1. Open Information Extraction from the Web
2. ReVerb
3. ClausIE
4. REBEL
5. UIE

目标：理解规则式、分类式和生成式抽取的基本差异。

### 第二阶段：理解现代实体与通用抽取

1. GLiNER
2. UniversalNER
3. GoLLIE
4. KnowCoder
5. Structured Entity Extraction

目标：理解开放类型、动态 Schema、标注指南、代码 Schema 和复杂实体结构。

### 第三阶段：从抽取走向知识图谱

1. EDC
2. OneKE
3. AutoSchemaKG
4. KARMA（作为系统对照，而不是基础理论）

目标：理解抽取、Schema 定义、规范化、验证和知识库写入之间的关系。

## 6. 最适合边做边学的项目

### 项目一：GLiNER 工业实体抽取基线

准备 20～50 段工业文本，定义：

```text
Equipment
Component
Material
Fault
ProcessParameter
Location
```

实验内容：

1. 运行零样本实体抽取；
2. 人工标注少量测试集；
3. 计算 Precision、Recall、F1；
4. 修改实体类型名称和描述；
5. 观察实体边界错误、类型混淆和漏抽问题。

### 项目二：基于 JSON Schema 的 LLM 抽取

定义一个小型工业 Schema：

```json
{
  "equipment": "",
  "component": "",
  "fault": "",
  "fault_location": "",
  "parameter": {
    "name": "",
    "value": null,
    "unit": ""
  },
  "evidence": ""
}
```

实验内容：

1. 使用同一批文本进行抽取；
2. 验证 JSON 格式；
3. 验证值是否确实出现在原文；
4. 比较 LLM 与 GLiNER 的实体结果；
5. 区分格式正确、Schema 正确和事实正确。

### 项目三：EDC 关系规范化

观察以下开放关系是否应映射为统一关系：

```text
installed_in
located_at
mounted_in
positioned_at
```

实验内容：

1. 抽取开放三元组；
2. 为关系生成定义；
3. 进行关系规范化；
4. 对比自动 Schema 与人工 Schema；
5. 分析错误合并和错误拆分。

### 项目四：OneKE 与简单基线比较

在同一数据、同一 Schema 下比较：

- 规则/正则；
- GLiNER；
- 单次 LLM JSON 抽取；
- OneKE；
- KARMA 中对应的抽取流程。

评价维度：

- 实体 Precision、Recall、F1；
- 关系三元组 F1；
- Schema 遵循率；
- 格式合法率；
- 幻觉率；
- 证据可追溯率；
- 调用次数、时间和成本。

## 7. 阅读每篇论文时统一回答的问题

不要一开始逐句翻译论文。每篇先回答：

1. 论文解决的具体问题是什么？
2. 输入和输出是什么？
3. Schema 是否预定义？Schema 如何表示？
4. 抽取对象是实体、属性、关系还是事件？
5. 方法是规则、分类、序列标注还是生成？
6. 是否使用 LLM？LLM 在哪个环节使用？
7. 是否真的需要 Agent？
8. 数据集来自哪里？是否与工业数据相似？
9. 使用了什么评价指标？
10. 与基线相比提高了什么？代价是什么？
11. 结果如何验证？是否检查幻觉和 Schema 违规？
12. 哪个思想可以迁移到工业知识抽取？

---

## 8. 当前不应作为重点的内容

现阶段暂不重点投入：

- RAG 和 GraphRAG；
- 知识图谱问答；
- KG 密度和补全；
- 多 Agent 角色数量设计；
- Agent 自演化和强化学习；
- DataAgent 应用；
- 与知识抽取无直接关系的摘要、机器翻译和事实验证任务。

这些内容可以在知识抽取方案、数据集和评价体系基本确定后再补充。

## 9. 当前最推荐的三个代码项目

1. GLiNER：https://github.com/urchade/GLiNER
   - 最容易运行；
   - 适合学习实体、类型、边界和基本评价。

2. EDC：https://github.com/clear-nus/edc
   - 最贴近 Schema induction、关系定义与规范化；
   - 适合学习从开放抽取到知识图谱的关键过渡。

3. OneKE：https://github.com/zjunlp/OneKE
   - 适合观察完整 Schema-guided LLM 知识抽取系统；
   - 可以与 KARMA 进行系统层面的对比。

建议实践顺序：

```text
GLiNER
  ↓
简单 JSON Schema + LLM
  ↓
EDC
  ↓
OneKE
  ↓
KARMA 对照实验
```

这条路线的目标是逐步把“知道论文和项目名称”转化为“能够解释输入输出、运行代码、评价结果并分析适用性”。
