# 11.3 反馈分步：输入、输出与执行顺序

反馈从拆分后的三元组开始，依次执行 Add → Replace → Remove。前面的重建文本、文本对比和实体反馈继续执行；后面的冲突处理、评分筛选与评估继续接收最终反馈结果。

## 每一步接收什么

三个 Agent 都接收完整源句、带当前 index 的三元组集合、源句到三元组的对应表、候选实体、重建文本与文本差异、前序实际修改记录，以及前序待处理问题。每个 Agent 都自主检查其负责的问题，不能只处理前序提示。

文本差异与重建文本标明来自初始集合 V0。后续修改不会自动重建文本或重新比较，因此 Agent 要结合当前集合和实际修改记录判断旧差异是否仍成立。

| 阶段 | 主要判断 | 输出与下一步输入 |
| --- | --- | --- |
| Add | 逐句检查完全遗漏的关系；已有错误或长字段中的嵌套关系交给 Replace | 输出 add 和问题清单；程序应用有效新增后，把整个新集合交给 Replace |
| Replace | 检查主语、字段、词形、必要限定与嵌套拆分；也检查刚新增的条目 | 每项 replace 指向一个旧 index，new_triples 包含一条或多条；程序替换后把整个集合交给 Remove |
| Remove | 自主比较全部条目，判断是否重复、保留哪条 | 每项 remove 指明删除 index 与保留 keep_index；程序删除后得到反馈结果 |

完整提示见 [Add](feedback_add/AddAgent_完整Prompt.md)、[Replace](feedback_replace/ReplaceAgent_完整Prompt.md)、[Remove](feedback_remove/RemoveAgent_完整Prompt.md)。共有规则由 [feedback_common.py](feedback_common.py) 拼接，不增加第四个模型调用。

## 编号和问题怎样传下去

S1 等编号表示源句，index 表示本次集合中的三元组位置，两者不同。程序在每步修改后重新建立 index 对应表：一条拆成两条时，旧 index 对应两个新 index；删除时对应空列表。

handoff.related_indices 会更新为下一步可用的编号；origin_indices 和 origin_version 保留原始定位。每个问题有独立 id，后续通过 handoff_results 说明已解决、仍需处理、不同意前序判断或无法确定。

例如 Add 发现第 2 条 tail 中含有未拆出的关系，把第 2 条交给 Replace。Replace 将其换成两条后，Remove 收到实际产生的两条及更新后的编号，不再拿旧编号操作新集合。

主流程结束后，如果仍有明确交给 Add 或 Replace 的未解决问题，最多再执行一轮返修：需要 Add 时执行 Add → Replace → Remove；只需 Replace 时执行 Replace → Remove。返修后仍有问题则保留记录，不无限循环。指向重建文本、文本对比或人工核查的问题只记录，不自动重跑这些阶段。

## 程序检查和失败处理

程序校验 JSON 结构、阶段操作权限、检查范围、当前编号、问题引用、有效源句编号、逐字证据和评分范围。每条新增或替换结果必须自己提供来源与证据。

Add 中有效操作可继续执行，无效操作单独记录。Replace 和 Remove 中任一操作无效时，本步整批不执行，以免相互依赖的修改只执行一部分。调用、解析或整体格式失败时，保留该步输入，记录失败，再交给后续阶段检查。

程序不自动判断语义重复，也不通过代码悄悄去重；是否重复及保留哪个由 Remove 判断。上述格式校验不能保证模型的语义判断一定正确。

## 运行后查看哪些文件

- `revision_result.json` 保留 baseline、after_split、after_revision，并新增 after_add、after_replace。after_add 与 after_replace 是首次顺序执行的快照；after_revision 包含可能发生的有限返修结果。
- 每篇的 `_dump_doc{i}_feedback_{序号}_{阶段}.json` 保存该次输入、实际 System/User 消息、原始回复、解析结果、接受或拒绝的操作、编号对应表和输出。
- 原 `_dump_doc{i}_r1_revision.json` 保存三步反馈总审计，包括各步记录和 unresolved_issues。存在格式或执行失败时标记 completed_with_errors；是否仍有语义待核查问题需查看 unresolved_issues。

控制流程见 [feedback_pipeline.py](../core/feedback_pipeline.py)，操作校验与应用见 [feedback_operations.py](feedback_operations.py)，主程序接入见 [pipeline.py](../core/pipeline.py)。relationship_extraction 中仅保留基线抽取提示，反馈提示已移到三个新 Agent 及共享规则文件。

## 验证范围

已用离线模拟回复检查三步衔接、一条换多条、编号更新、来源保留、重复删除、失败回退、有限返修，以及原有完整流程与回放流程。真实模型能否改善三元组质量，需要用新运行结果继续评估；代码测试不等于 P、R、F1 已提升。
