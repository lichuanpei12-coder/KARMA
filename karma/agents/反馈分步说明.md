# 三个反馈 Agent 的分工和执行顺序

拆分后的三元组作为初始集合 V0。程序按 Add → Replace → Remove 的顺序执行，每个 Agent 都基于源句和当前集合独立核查。默认每句分别运行三次反馈，整篇模式每篇运行三次反馈。

| Agent | 检查重点 | 同一次回复中可以完成的处理 |
| --- | --- | --- |
| Add | 源句中的独立事实或必要成分有无遗漏 | 补充遗漏事实，直接补全已有条目，或从长字段中拆出遗漏的关系并整理外层关系 |
| Replace | 已有表达的主体、方向、词形、限定和字段边界 | 替换或拆分条目，同时补回遗漏或清理本次修正涉及的重复项 |
| Remove | 当前集合中的重复和部分重叠 | 确定完整的保留表达，修正保留项、删除重复项，并保住各条所含的独立事实 |

输入包含源句、当前集合、源句编号对应表、实体候选、基于 V0 的重建和差异、此前实际操作的摘要。Remove 还会收到依据当前集合重新计算的词重合排名。重建文本或差异提示有误时，依据原句保留正确的三元组。

## 输出与执行

三个 Agent 都输出 add、replace、remove 三个数组。replace 是当前 Agent 对某个输入编号执行的替换操作，一条可换成多条。删除重复项时 keep_index 指明保留条目。删除有明确反证且无法修正的条目时，keep_index 为 null 并说明理由。

每次回复都使用该次输入编号。涉及替换或删除时，一组操作一起校验、一起生效。仅有独立新增的 Add 回复，可以接受合法新增并逐项记录拒绝原因。下一阶段读取已应用的结果和重新编号的集合。格式错误与执行失败记录在当前运行的 review_issues 中。

完整提示见 [Add](feedback_add/AddAgent_完整Prompt.md)、[Replace](feedback_replace/ReplaceAgent_完整Prompt.md)、[Remove](feedback_remove/RemoveAgent_完整Prompt.md)。

## 固定分数与旧数据

基线抽取和三步反馈的模型输入、规则及输出要求均不含 confidence、clarity、relevance。程序为三元组统一填入 0.8；拆分、反馈、后续冲突处理和阈值筛选使用这一固定值。回放旧数据时只在工作副本中统一分数，保存的旧基线文件保持原样。

0.8 是兼容现有数据结构的固定值，不再表示模型对事实的质量判断。现有阈值筛选仍执行：阈值高于 0.8 时会过滤这些三元组。现有冲突规则仍执行，相同固定分数按原来的同分逻辑处理。Reader 的段落相关性评分继续用于段落筛选，与三元组固定分数分开。

模型收到的修改记录仅保留前后事实与失败摘要，完整记录和历史编号继续保存在审计文件。所有三元组修改仍需源句依据，固定分数不替代事实核查。

## 运行后核对结果

- 在 `revision_result.json` 中比较 after_split、after_add、after_replace 和 after_revision，观察每次反馈立即生效的变化。
- 各步的反馈明细保存输入、实际消息、原始回复、接受或拒绝的操作、编号映射及输出。按阶段和 operation 能确定由哪个 Agent 执行了哪项修改。
- 整篇审计协议为 direct_operations_v1，逐句汇总协议为 sentence_direct_operations_v1。历史运行的转交及返修记录按当时的协议解读。
